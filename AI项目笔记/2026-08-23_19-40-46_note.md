# 部署 HTML 汇总到 GitHub Pages

## 本次完成
将 HTML 导出脚本、测试和生成结果上传到 GitHub，并加入自动生成首页与 GitHub Pages 部署工作流；远程仓库尚未首次启用 Pages，因此站点当前未上线。

## 关键改动
- `scripts/export_summaries.py`：导出汇总后自动生成包含所有项目链接的 `HTML汇总/index.html`。
- `tests/test_export_summaries.py`：增加首页及 URL 编码链接验证。
- `.github/workflows/pages.yml`：在 `main` 的汇总或脚本变化后，使用 GitHub 官方 Actions 自动导出并部署静态站点。
- `README.md`：补充预期站点地址。

## 验证结果
- `python3 -m py_compile`：脚本与测试语法通过。
- `python3 -m unittest -v tests.test_export_summaries`：1 项测试通过。
- `python3 scripts/export_summaries.py`：3 个项目页面和 1 个站点首页生成成功。
- `git push origin main`：提交已上传到 GitHub。
- `curl https://luckyt1.github.io/note/`：连续 6 次返回 404，确认仓库尚未首次启用 GitHub Pages。

## 值得学习
- GitHub Pages 自定义工作流可以持续部署静态产物，但首次启用 Pages 属于仓库管理操作；默认 `GITHUB_TOKEN` 不能代替用户打开该功能。

## 决策与取舍
- 采用 GitHub 官方 Pages Actions，而不是维护容易失去同步的 `gh-pages` 分支；保留 Markdown 为源内容，工作流每次重新生成 HTML。

## 后续事项
- 在仓库 Settings → Pages 中将 Build and deployment 的 Source 设为 GitHub Actions；私有仓库还需确认当前 GitHub 套餐支持 Pages。
