## 创建自动 Obsidian 项目笔记 Skill
<!-- obsidian-project-note-source: 2026-08-23_14-32-01_Codex Skills.md -->

- 创建时间：`2026-08-23T14:31:21+08:00`
- 原始笔记：`2026-08-23_14-32-01_Codex Skills.md`

### 本次完成
创建并全局安装 `obsidian-project-note` Skill。以后 AI 完成会修改项目文件的开发任务后，会在 Obsidian 的 `note` 仓库中生成一篇中文笔记，总结完成内容、验证结果、决策取舍和值得学习的知识。

### 关键改动
- `SKILL.md`：定义自动触发边界、笔记模板、隐私规则和完成后的保存流程。
- `agents/openai.yaml`：启用隐式调用，并提供中文名称与说明。
- `scripts/save_note.py`：使用 Python 标准库把准备好的 Markdown 安全写入 `AI项目笔记/`，自动生成唯一文件名并清理非法字符。

### 验证结果
- `quick_validate.py`：Skill 结构与 frontmatter 校验通过。
- `python3 -m py_compile`：保存脚本语法检查通过。
- 隔离仓库写入测试：目录创建、文件名清理、内容一致性和必需标题检查全部通过。
- 安装后文件比对：全局安装内容与已验证版本一致。

### 值得学习
- Obsidian 仓库本质上是 Markdown 文件目录，直接写入 `.md` 文件即可被 Obsidian 识别，不要求 GUI 常驻。
- Skill 的 `description` 决定自动发现和隐式触发的准确度，应同时写清适用任务与不适用边界。
- 重复且容易出错的保存逻辑适合放进无第三方依赖的小脚本，正文内容仍由 AI 根据真实任务生成。

### 决策与取舍
- 系统未注册 `obsidian` CLI，因此选择直接写入 Obsidian 1.12.7 已配置的仓库，而不是依赖 AppImage GUI 或 URI 协议。
- 仅创建 Skill、界面元数据和一个保存脚本，没有增加额外依赖或修改项目仓库。

### 后续事项
- 新的 Codex 会话会自动发现该全局 Skill；若当前会话没有刷新 Skill 列表，重新开启会话即可。

## 为 Obsidian 项目笔记增加每小时自动汇总
<!-- obsidian-project-note-source: 2026-08-23_15-55-38_Codex Skills.md -->

- 创建时间：`2026-08-23T15:54:57+08:00`
- 原始笔记：`2026-08-23_15-55-38_Codex Skills.md`

### 本次完成
扩展 `obsidian-project-note` Skill，新增每小时运行的项目笔记整理器。它按 frontmatter 中的 `project` 精确分组，把内容追加到 `AI项目汇总/<项目>/项目汇总.md`，确认汇总文件已可靠写入后自动删除 `AI项目笔记` 中的原始笔记。

### 关键改动
- `scripts/merge_notes.py`：实现按项目分组、可读的 Markdown 合并、重试去重、进程锁、原子写入与成功后删除。
- `scripts/save_note.py`：增加 frontmatter 合约校验、并发排他创建和长 UTF-8 项目名处理，避免原始笔记在进入汇总前被覆盖或无法保存。
- `SKILL.md` 与 `agents/openai.yaml`：记录自动整理流程并更新 Skill 的界面说明。
- `~/.config/systemd/user/obsidian-project-note-merge.service`：定义一次性整理服务。
- `~/.config/systemd/user/obsidian-project-note-merge.timer`：登录后启动并每 1 小时触发；已启用 linger，退出桌面登录后也会继续运行。

### 验证结果
- `python3 /tmp/test_merge_notes.py -v`：4 个回归测试通过，覆盖分组删除、失败保留、重复重试、并发保存、frontmatter 校验和超长 emoji 项目名。
- 独立只读复审：最终无 HIGH/MEDIUM 问题。
- `systemd-analyze --user verify`：service 与 timer 单元校验通过。
- 首次真实合并：8 篇原始笔记成功合并为 3 个项目汇总，8 个来源标记全部存在，原始笔记目录清空。
- `systemctl --user list-timers`：timer 为 active/enabled，下一次运行时间是 2026-08-23 16:53:57 CST。
- `loginctl show-user tang -p Linger`：`Linger=yes`。

### 值得学习
- 自动删除源文件的流程必须先原子写入目标、执行 `fsync`，再删除源文件；否则异常或断电可能造成不可恢复的数据丢失。
- 使用唯一来源标记能让中断后的重试保持幂等：已合并内容不会重复，残留源文件仍可安全删除。
- `os.link()` 可以在同一文件系统内原子且排他地发布已经写好的文件，避免多个 AI 同一秒保存时互相覆盖。
- 用户级 systemd timer 比依赖桌面应用运行的 Codex Scheduled Tasks 更适合固定周期整理工作区外的本机 Obsidian 仓库。

### 决策与取舍
- 采用 Python 标准库加 systemd，没有增加第三方依赖。
- 汇总文件保留每篇笔记的完整结构化内容，而不是再次调用 AI 改写，避免定时任务产生含义漂移或遗漏。
- 无法解析 `project` 的异常笔记不会删除，会留在收集箱供人工修复。

### 后续事项
- 无

## 制作 Obsidian AI 项目笔记系统迁移包
<!-- obsidian-project-note-source: 2026-08-23_17-13-27_Codex Skills.md -->

- 创建时间：`2026-08-23T17:12:54+08:00`
- 原始笔记：`2026-08-23_17-13-27_Codex Skills.md`

### 本次完成
把自动项目笔记 Skill、保存与合并脚本、systemd 定时器和迁移说明整理为一个便携压缩包，并连同外层 README 和 SHA256 校验文件保存到 Obsidian 仓库的 `AI项目笔记系统迁移包/`。后续同步整个仓库到云端即可同时保存笔记数据和恢复工具。

### 关键改动
- `AI项目笔记系统迁移包/README.md`：说明云端同步范围、旧设备停用 timer、新设备安装和验证步骤。
- `AI项目笔记系统迁移包/obsidian-project-note-portable.tar.gz`：包含完整 Skill、脚本、systemd 单元、内层 README、安装器和文件清单。
- `AI项目笔记系统迁移包/SHA256SUMS`：校验迁移压缩包完整性。
- `install.sh`：接受新 Obsidian 仓库路径和 Skill 目录，自动替换旧设备路径；遇到已有 Skill、service 或 timer 时拒绝覆盖。

### 验证结果
- `sha256sum -c MANIFEST.sha256`：压缩包内所有文件校验通过。
- 隔离 HOME/Vault 安装：Skill 路径和仓库路径替换正确，Skill 结构校验通过。
- 隔离保存与合并：成功创建笔记、生成项目汇总并删除已合并源笔记。
- 覆盖保护测试：存在自定义 systemd unit 时安装器在写入前拒绝，原文件保持不变。
- `systemd-analyze --user verify`：迁移后 service 与 timer 语法通过。
- 最终归档重新解压：文件列表、两层 SHA256、安装脚本语法和 Skill 校验全部通过。
- 独立只读复审：最终无 HIGH/MEDIUM 问题。

### 值得学习
- 可移植配置不能只复制文件，还必须显式替换 Skill 安装路径、Obsidian 数据路径和 systemd `ExecStart` 路径。
- 外层压缩包校验与内层逐文件清单可以分别发现传输损坏和包内文件篡改。
- 云同步的文件锁通常不能跨设备可靠工作，同一个仓库应只让一台设备运行自动整理 timer。
- 迁移包与数据放在同一 Obsidian 仓库中，可以避免工具和笔记备份生命周期分离。

### 决策与取舍
- 压缩包不重复包含 `AI项目笔记/` 和 `AI项目汇总/` 数据，避免云端产生两份笔记；数据通过整库同步迁移。
- 默认采用 OpenAI 官方用户级 `$HOME/.agents/skills`，同时允许通过 `--skill-root` 兼容 `$HOME/.codex/skills`。
- 安装器拒绝自动覆盖已有配置，迁移或升级时需要先显式重命名备份。

### 后续事项
- 真正切换设备前，先在旧设备执行 `systemctl --user disable --now obsidian-project-note-merge.timer`，等待云同步完成后再在新设备启用。
