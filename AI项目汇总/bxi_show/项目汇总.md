## 优化 ESP32-S3 快速烧录入口
<!-- obsidian-project-note-source: 2026-08-25_19-40-20_bxi_show.md -->

- 创建时间：`2026-08-25T19:39:59+08:00`
- 原始笔记：`2026-08-25_19-40-20_bxi_show.md`

### 本次完成
将完整固件与烧录脚本移到项目根目录，并把 Linux 串口选择改为数字编号交互；选择后自动提示管理员密码并执行指定的串口授权命令，降低现场烧录的操作门槛。

### 关键改动
- `flash_firmware.py`：串口按编号选择，Linux 自动执行 `sudo chmod 777 <串口>` 并提示密码输入不可见。
- `LVGL_Arduino_full.bin`：无内容变化地搬到项目根目录。
- `tests/test_flash_firmware.py`：覆盖编号选择、授权命令和主流程自动授权。
- `README.md`、`ESP32-S3-Touch-LCD-2.1-Demo/Arduino/examples/LVGL_Arduino/DISPLAY_SETUP.md`：同步根目录用法和权限说明。

### 验证结果
- `python3 -m unittest tests/test_flash_firmware.py`：3 条测试通过。
- `python3 flash_firmware.py --check-only`：Python、esptool 和 16 MB 固件结构检查通过。
- `git hash-object` 对比：搬迁前后固件 Git 对象哈希一致。

### 值得学习
- 设备列表适合动态编号映射，用户只需输入短数字，同时仍可保留 `--port` 供自动化调用。
- 二进制文件搬迁后应比较内容哈希，避免仅凭文件大小判断完整性。

### 决策与取舍
- 保留旧的 `--fix-port-permission` 参数作为兼容入口，但 Linux 主流程不再要求用户手动添加该参数。

### 后续事项
- 未连接真实 ESP32-S3 执行烧录；硬件连接与写入流程仍需现场验证。
