## 增加一键仿真测试启停脚本
<!-- obsidian-project-note-source: 2026-08-25_15-06-45_3D-nav-dev.md -->

- 创建时间：`2026-08-25T11:47:59+08:00`
- 原始笔记：`2026-08-25_15-06-45_3D-nav-dev.md`

### 本次完成
增加一键启动和停止入口，自动复用现有 ELF3 仿真策略与 3D 建图脚本，并用独立进程组、PID 文件和日志文件管理后台测试进程。

### 关键改动
- `start.sh`：缺少完整安装产物时自动构建，依次启动仿真策略和建图，阻止重复启动并在失败时清理已启动进程。
- `stop.sh`：按 PID 文件向整个进程组发送 TERM，超时后发送 KILL，支持重复执行。

### 验证结果
- `bash -n start.sh stop.sh`：通过，两个脚本语法正确且具有执行权限。
- 隔离 `sleep` 进程组冒烟：真实会话 PID 写入、重复启动拦截、失败清理和停止后 PID 文件删除均通过。
- `./start.sh`：首次构建被现有环境依赖阻断；缺少 Pangolin，且 PCL/VTK 引用的 `MPI::MPI_C` 目标不存在，未进入 ROS 全链路启动。
- 残留检查：无 `colcon build`、目标 ROS launch 或运行 PID 文件残留。

### 值得学习
- `setsid` 在调用进程恰好是进程组组长时可能自行 fork，因此不能无条件把 shell 的 `$!` 当作新会话 PID；由新会话内进程回写 `$$` 更可靠。

### 决策与取舍
- 复用仓库已有启动脚本并以进程组停止，未采用宽泛 `pkill`，避免误伤同机其他 ROS 进程。

### 后续事项
- 安装 Pangolin，并修复当前 PCL/VTK 的 MPI C 目标配置后，再执行 `./start.sh` 完成 ROS 全链路冒烟。

## 编译 3D-nav-dev 并补齐依赖
<!-- obsidian-project-note-source: 2026-08-25_15-26-38_3D-nav-dev.md -->

- 创建时间：`2026-08-25T15:26:07+08:00`
- 原始笔记：`2026-08-25_15-26-38_3D-nav-dev.md`

### 本次完成
补齐 ROS 2 Humble 运行/编译依赖并完成工作区构建，15 个项目包全部通过。解决了 Pangolin/RTAB-Map 依赖缺失，以及 PCL/VTK 查找 OpenMPI C 目标失败两个阻塞点。

### 关键改动
- `src/bxi_example_nav3d/bxi_octo_global_planner/CMakeLists.txt`：为项目同时启用 C 与 CXX，使 PCL/VTK 能创建并链接 `MPI::MPI_C`。
- 系统依赖：安装 Pangolin、depth-image-proc、RTAB-Map launch/odom/slam/sync/msgs/rviz 插件和 imu-filter-madgwick 等 ROS 包及传递依赖。

### 验证结果
- `./build.sh`：全量构建 15/15 成功；再次增量构建 15/15 成功。
- `ros2 pkg prefix bxi_example_py_elf3 bxi_scan_nav bxi_orbslam3_ros2`：三个关键包均解析到本工作区 `install`。
- `colcon test --merge-install --packages-select scan_planner`（`ROS_LOG_DIR=/tmp/3d-nav-ros-logs`）：2/2 通过。
- `ctest --test-dir build/remote_controller -R 'remote_controller_(crsf_frame_parser|control_rules)_test'`：2/2 核心单元测试通过。
- `rosdep check --from-paths src --ignore-src -r`：系统依赖均满足；仅 `ament_python` 在当前 rosdep 数据中无映射。

### 值得学习
- 当 PCL/VTK 报 `MPI::MPI_C` 不存在而 OpenMPI 已安装时，应检查顶层 CMake 是否只启用了 CXX；`project(... LANGUAGES C CXX)` 才会让 CMake 的 MPI 查找创建 C 目标。

### 决策与取舍
- 优先使用 apt/ROS 官方二进制包补齐已有 manifest 依赖；没有引入源码编译的第三方副本。仅对真实的 CMake 语言声明根因做一行修复。

### 后续事项
- 全量 `colcon test` 仍会因 `remote_controller` 现有版权/格式 lint，以及 `bxi_example_py_elf3` 配置了不存在的 `test/` 目录而失败；功能测试已单独通过。未启动仿真/rviz。

## 恢复启动实时日志与 RViz 点云
<!-- obsidian-project-note-source: 2026-08-25_16-36-15_3D-nav-dev.md -->

- 创建时间：`2026-08-25T16:35:49+08:00`
- 原始笔记：`2026-08-25_16-36-15_3D-nav-dev.md`

### 本次完成
让 `start.sh` 启动后持续输出策略与建图日志，并修复 RTAB-Map 组件无法加载、RViz 点云 QoS 不兼容导致的空白显示。

### 关键改动
- `start.sh`：启动后使用 `tail -F` 实时跟随两份日志；系统缺失新版本动态库时加载项目内本地 ROS overlay。
- `src/bxi_example_nav3d/bxi_scan_nav/config/elf3_rtab_mapping.rviz`：将 `/rtabmap/cloud_map` 的 Durability 改为 `Volatile`，与发布端一致。

### 验证结果
- `bash -n start.sh`：通过。
- `colcon build --merge-install --packages-select bxi_scan_nav`：构建通过。
- `ros2 topic info /rtabmap/cloud_map --verbose`：发布端与 RViz 订阅端均为 Reliable + Volatile，订阅者为 1。
- `ros2 topic echo --once /rtabmap/cloud_map --field header`：收到 `frame_id: world` 的实时消息。

### 值得学习
- RViz 空白要同时检查发布端是否存在、组件动态库是否成功加载，以及 DDS QoS 是否兼容；topic 存在不代表订阅能收到数据。
- ROS deb 包更新不同步会出现已安装依赖却缺失新 ABI 动态库的情况，应结合 `dlopen` 错误和包版本定位。

### 决策与取舍
- 因系统升级需要 sudo 密码，使用官方 deb 解出的本地 overlay 临时恢复；系统包未来升级后 `start.sh` 会优先使用系统动态库。

### 后续事项
- 有 sudo 权限时可执行 `sudo apt install --only-upgrade ros-humble-diagnostic-updater`，之后本地 overlay 将不再被使用。
