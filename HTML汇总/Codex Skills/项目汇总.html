扩展 obsidian-project-note Skill，新增每小时运行的项目笔记整理器。它按 frontmatter 中的 project 精确分组，把内容追加到 AI项目汇总/<项目>/项目汇总.md，确认汇总文件已可靠写入后自动删除 AI项目笔记 中的原始笔记。

关键改动

  • scripts/merge_notes.py：实现按项目分组、可读的 Markdown 合并、重试去重、进程锁、原子写入与成功后删除。
  • scripts/save_note.py：增加 frontmatter 合约校验、并发排他创建和长 UTF-8 项目名处理，避免原始笔记在进入汇总前被覆盖或无法保存。
  • SKILL.md 与 agents/openai.yaml：记录自动整理流程并更新 Skill 的界面说明。
  • ~/.config/systemd/user/obsidian-project-note-merge.service：定义一次性整理服务。
  • ~/.config/systemd/user/obsidian-project-note-merge.timer：登录后启动并每 1 小时触发；已启用 linger，退出桌面登录后也会继续运行。

验证结果

  • python3 /tmp/test_merge_notes.py -v：4 个回归测试通过，覆盖分组删除、失败保留、重复重试、并发保存、frontmatter 校验和超长 emoji 项目名。
  • 独立只读复审：最终无 HIGH/MEDIUM 问题。
  • systemd-analyze --user verify：service 与 timer 单元校验通过。
  • 首次真实合并：8 篇原始笔记成功合并为 3 个项目汇总，8 个来源标记全部存在，原始笔记目录清空。
  • systemctl --user list-timers：timer 为 active/enabled，下一次运行时间是 2026-08-23 16:53:57 CST。
  • loginctl show-user tang -p Linger：Linger=yes。

值得学习

  • 自动删除源文件的流程必须先原子写入目标、执行 fsync，再删除源文件；否则异常或断电可能造成不可恢复的数据丢失。
  • 使用唯一来源标记能让中断后的重试保持幂等：已合并内容不会重复，残留源文件仍可安全删除。
  • os.link() 可以在同一文件系统内原子且排他地发布已经写好的文件，避免多个 AI 同一秒保存时互相覆盖。
  • 用户级 systemd timer 比依赖桌面应用运行的 Codex Scheduled Tasks 更适合固定周期整理工作区外的本机 Obsidian 仓库。

决策与取舍

  • 采用 Python 标准库加 systemd，没有增加第三方依赖。
  • 汇总文件保留每篇笔记的完整结构化内容，而不是再次调用 AI 改写，避免定时任务产生含义漂移或遗漏。
  • 无法解析 project 的异常笔记不会删除，会留在收集箱供人工修复。
